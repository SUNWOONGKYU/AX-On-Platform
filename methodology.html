① SAL GRID

SAL Grid — Stage × Area × Level 3차원 좌표계

SAL Grid는 AX 프로젝트의 모든 Task를 Stage·Area·Level 3개 축으로 분해하여 정리합니다. 각 Task는 자신만의 좌표(예: S1TR1)를 갖습니다.

3개 축

S
Stage
업무 흐름 단계 — 선후 의존성을 가진 시간축 (S1 → S2 → … → Sn)
A
Area
Areas 중 어느 영역
L
Level
각 셀 내 실행 항목 순서

Stage 정의 (S축) — 산업·조직별로 다름

Stage는 각 산업·조직의 본업 업무 흐름을 따라 정의됩니다. 앞 Stage가 끝나야 다음 Stage가 시작되는 선후 의존성을 갖습니다.

산업업무 흐름 (S1 → … → Sn)
엔지니어링영업/수주 → 착수/계획 → 조사·분석 → 설계·용역수행 → 검토·납품 → 사후관리
건설사업기획 → 설계 → 분양 → 시공 → 준공/사후
아카이브구축상담 → 아카이브설계 → 자료수집 → 디지털화·메타 → 시스템등록 → 운영·서비스 → 사후관리

각 Task의 좌표는 S{Stage}{Area}{Level}{Variant?} 형식의 단일 문자열로 인코딩됩니다. 식별자만 보고도 어느 Stage·Area·Level의 Task인지 파싱이 가능합니다.

5가지 효과

EFFECT 1
No-Code 프로젝트 정의
코드 없이 Stage × Area 매트릭스 채우기만으로 프로젝트 구조 정의. 누구나 SAL ID만으로 작업 정의 가능.
EFFECT 2
자기설명적 식별자
자동 증가 번호(#1234)와 달리 SAL ID(S3BA2a)는 좌표·의존성·병렬성·인접성을 식별자 자체에 내재.
EFFECT 3
3D 위상 위의 의존성 자동 결정
Stage 순서 → 시간축 의존성 / Area 인접 → 영역 간 인접성 / Level → 절차적 깊이가 좌표만으로 결정됨.
EFFECT 4
실행–검증 일체화
Task 지시서와 검증 지시서가 동시에 생성되어, 실행 직후 검증 결과까지 동일 좌표에 기록.
EFFECT 5
Stage Gate 기반 자가 치유
Stage 미완료 시 다음 Stage 진입 차단. 검증 리포트가 누락된 작업을 자동 식별 → 보완 사이클 진입.

② PLATOON FORMATION

Platoon Formation — AI 에이전트의 소대 편제

군 소대 편제 원리를 AI 에이전트 팀 편성에 응용합니다. 소대장 · 분대장 · 분대원 · 용병(외부 AI)의 4계층으로 구성되며, 사용자(지휘관) 개입은 임무 부여 · 작전 개시 승인 · 해산 승인 3회로 제한됩니다.

군사용어 ↔ 기술용어 대응

군사 편제 용어는 계층적 역할과 지휘 관계를 직관적으로 표현하기 위한 기술적 비유(Technical Analogy)입니다.

편성 공식

작업팀 총원 = P + N × {1 + M} + K
P 본부 정원 (소대장 + 연락병) N 분대 수 M 분대당 분대원 수 K 용병(외부 AI) 수
예: P=2, N=3, M=11, K=4 → 총원 42명 (본부 2 + 3분대×12 + 용병 4)

분대 수 3~5의 근거 — Span of Control

한 명의 지휘관이 효과적으로 통제할 수 있는 하위 단위는 3~5개입니다. 이 원리는 군사학·실전 군대·AI 에이전트 분야에서 모두 일관되게 확인됩니다.

  • 미 해병대 지휘통제 교리 (MCDP 6, 1996) — 한 지휘관의 효과적 통제 범위는 3~5개. 3개 하위 단위는 2개보다 유연하고 통제 가능 범위 유지.
  • 전 세계 군대의 보편 편성 — 대한민국 육군(소총소대 3개 분대), 미 육군(보병소대 3+1), 독일 연방군(Zug 3 Gruppen), 일본 육상자위대(3개 소총분대), 프랑스 육군(3개 전투조).
  • RAND Research Report RR-184 — 분대→소대(×3)→중대(×3)→대대(×3)의 계층적 확장이 3의 배수로 이루어진다는 패턴 확인.
  • Anthropic Claude Code Agent Teams (2025) — "Start with 3-5 teammates for most workflows. Three focused teammates often outperform five scattered ones." AI 에이전트 분야에서도 동일 원리 확인.

5가지 효과

EFFECT 1
예측 가능한 편성
편성 공식 P+N×{1+M}+K로 프로젝트 규모와 무관하게 일관된 팀 구조 형성.
EFFECT 2
통신 경로 94.8% ↓
평면 구조 O(n²) 861개 → 계층 구조 O(n) 45개 (42명 기준). 토큰 소비·API 비용·처리 시간 동시 감소.
EFFECT 3
동적 모델 배치 비용 절감
소대장 1(고급) + 분대장 3(중급) + 분대원 33(경량) = 전원 고급 대비 약 94.7% 비용 절감.
EFFECT 4
이종 AI 통합 운용
용병(외부 AI) 풀을 단일 게이트웨이로 집약. 연동 복잡도가 에이전트 수와 무관하게 K로 고정.
EFFECT 5
선형 확장 + 자율 운용
소대 단위 복제로 10소대(420명) · 100소대(4,200명) 선형 확장. 사용자 개입은 3회로 제한.

③ SAL TASK ANALYSIS

SAL Grid 좌표 위의 각 Task를 5개 Part(H·A·R·P·X), 25개 속성으로 분석합니다. "SAL Grid가 지도라면, STA는 그 지도 위의 각 지점을 탐사하는 도구"입니다.

R 산출 공식 — 우선순위 자동화의 핵심

H(현업 인터뷰)와 A(AI 자동수집)에서 모은 데이터를 4개 변수로 결합하여 자동화 우선순위를 정량화합니다.

R = (H4 + H5반전 + A6 + A7) × A10 ÷ A8
H4 반복성 (높을수록 자동화 효과 ↑) H5반전 예외·판단 (낮을수록 자동화 쉬움) A6 디지털화 수준 A7 업무 구조화 수준 × A10 예상 시간 절감량 (효과 가중) ÷ A8 오류 영향 심각도 (위험 페널티)
H5반전: 예외·판단이 높을수록 자동화 어려움 → 높음=1, 낮음=5로 반전 처리

Step 1·2 흐름 — 진단에서 실행까지

STA는 Step 1 진단(H · A · R)과 Step 2 추진(P · X)으로 분리됩니다. Step 1에서 우선순위가 매겨진 Task만 Step 2 추진 단계로 진입합니다.

  1. H현업 담당자 인터뷰 → 7개 항목 수집
  2. A시스템 로그·조직도 분석 → AI가 11개 항목 자동 수집
  3. R공식 적용 → 점수순 자동 정렬 (Step 1 종료)
  4. P상위 Task에 분대(Alpha/Bravo/Charlie/Delta) + 목표일 배정
  5. X실행 · 진행률 추적 · 이슈 기록 · 검증 (Step 2 종료)

적용 규모

SCALE 1

엔지니어링 용역(KD 적용 사례) 기준. 한 프로젝트 진단에 2,250개의 분석 셀이 자동 채워짐.
SCALE 2

SCALE 3

흐름: H(인터뷰) → A(AI 자동수집) → R(순위 산출) — 여기까지가 진단. → P(계획) → X(실행·검증) → 다음 Task.
