# AX-On Platform 디자인 개선계획서

**작성일**: 2026-04-28 (개정 2026-04-28)
**기반**: 3 페르소나 (Apple HIG / Stripe·Linear / 한국 시니어 UX·접근성) 검토
**범위**: **순수 디자인 개선만**. 사업 동선 신설(신규 CTA), 법인 설립 후 처리할 항목(사업자번호·Trust Stack), 데이터·인물 확보 후 처리할 항목(어드바이저·Logo Cloud)은 본 계획서에서 **제외**.

---

## 디자인 철학 (3 페르소나 합의문)

> **"메시지의 정직함 + 결정 가능한 동선 + 모두를 위한 가독성."**
>
> 모든 디자인 결정은 다음 3 게이트를 통과해야 한다:
> 1. 이 요소가 **메시지 전달에 필수**인가? (Apple HIG)
> 2. 이 요소가 **의사결정자의 다음 행동**을 만드는가? (Stripe/Linear)
> 3. 이 요소가 **50대 한국인이 안경 없이** 읽을 수 있는가? (WCAG AA + 한국화)

## P1 — 다음 스프린트 (구조 변경 동반)

### Phase 1.1 — Hero 재설계

**문제**: 현재 Hero는 텍스트 중앙정렬 800px 박스 + 좌우 거대 radial blob 2개. B2B SaaS 답지 않고 미니멀에도 어긋남.

**합의안**:
- [ ] 좌우 2-컬럼 레이아웃 (1280px max-width 활용)
- [ ] 좌측: 카피 + 기존 CTA (현재 동선 유지, 신규 CTA 추가하지 않음)
- [ ] 우측: **5 Phases 다이어그램 (한글 라벨)** — 단색 라인, 그래디언트 없음
- [ ] `::before` `::after` radial blob 두 개 모두 삭제
- [ ] H1 `clamp(36, 5vw, 56)px`로 확대 (현재 28~42)
- [ ] 다이어그램은 SVG 1개 파일로 분리 (`assets/diagrams/5-phases.svg`)

**의사결정 필요**:
- Q. 5 Phases 다이어그램 시각 스타일 — 박스 5개 일렬 / Stage Gate 형태 / 원형 시계방향?

### Phase 1.2 — 카피 톤·위계 정돈 (CTA 동선은 그대로)

**범위**: 새로운 CTA·동선을 추가하지 않는다. **현재 카피의 톤·길이·강조만 정리.**

**합의안**:
- [ ] H1 카피 길이 단축 + 핵심 메시지 한 줄 정착
- [ ] 마케팅 어휘 정리 ("5분 만에", "시뮬레이션" 류 과장 표현 제거)
- [ ] 2차 링크 라벨 통일 ("보기/알아보기" 혼용 → 일관 표현)
- [ ] 정중한 한글 톤 유지 (Outcome 동사 강요 X)

### Phase 1.3 — 타이포 위계 4-tier

**문제**: H1·H2·H3 모두 weight 800/900 + Noto Sans KR 400/700만 로드 → fake-bold.

**합의안**:
- [ ] Noto Sans KR `300;400;500;700;900` 5단계 로드 (또는 가변 폰트)
- [ ] 위계 정립:
  - H1 (Hero) = 900, clamp(36, 5vw, 56)
  - H2 (Section) = 800, clamp(28, 4vw, 42)
  - H3 (Card title) = 700, 18~20px
  - Lead (H2 직하) = 500, 20~22px, color: var(--ink)
  - Body = 400, 16px, color: var(--ink-muted)
- [ ] eyebrow caps 13px + letter-spacing 1.5px (이미 일부 적용)

### Phase 1.4 — 외래어 한글 병기

**문제**: DID·SAL Grid_AX·STA·H·A·R·P·X 등 영문 약어 폭격 → 시니어 인지 부하.

**합의안**:
- [ ] 첫 등장 시 한글 풀이 의무화
  - DID System → **"DID System (데이터→정보→의사결정 흐름 체계)"**
  - SAL Grid_AX → **"SAL Grid_AX (Stage·Area·Level 3차원 좌표계)"**
  - STA → **"SAL Task Analysis (이하 STA)"**
  - Platoon Formation → **"Platoon Formation (소대 편제 협업 운용)"**
- [ ] index.html Hero 카피 첫 문장에 영문 약어 사용 금지 — 순수 한글
- [ ] about-ax.html 또는 별도 글로싸리 페이지 신설 검토

## P2 — 후순위 (구조 변경 최소)

### Phase 2.1 — 디자인 토큰 강제 적용

**문제**: `--radius-sm/--radius/--radius-lg` 정의했으나 실제 사용은 `14px / 12px / 50px` 혼재.

**합의안**:
- [ ] `border-radius` 값 일괄 검사 → 모두 토큰화
- [ ] `--radius` 28px → 16px, `--radius-lg` 28px → 24px로 축소
- [ ] 신규: `--radius-pill: 999px` (배지 전용)

### Phase 2.2 — Hover 4-tier 토큰화

**문제**: 모든 호버가 `translateY(-2~-4px) + shadow 증대` 동일 패턴 → "전부 클릭 가능" 평탄화.

**합의안**:
- [ ] `--hover-cta-primary`: scale 1.02 + amber-glow
- [ ] `--hover-card`: translateY -2px + shadow-card
- [ ] `--hover-link`: color shift only (var(--ink))
- [ ] `--hover-nav`: background tint (rgba ink/0.04)
- [ ] 페이지별 적용 일관화

### Phase 2.3 — Empty State 시각 정돈

**문제**: pool/community 검색 0건 시 안내 부족 + 시각이 너무 비어 있음.

**합의안 (디자인 한정)**:
- [ ] 0건 안내 문구 위계 정리 + 보조 안내 한 줄 추가
- [ ] 일러스트는 단색 라인 SVG (이모지 사용 금지 규칙 연속)
- [ ] 여백·정렬·색상 통일 (페이지마다 다른 빈 화면 톤 일치)

### Phase 2.4 — 컬러 팔레트 격리

**문제**: amber·coral·teal·violet·sky 5개 hue 동시 등장 → "색맹 검사표".

**합의안**:
- [ ] amber: 브랜드·primary CTA 전용
- [ ] ink/ink-muted: 모든 텍스트
- [ ] teal/coral/violet/sky: `.chart` `.viz` 네임스페이스로 격리 (데이터 시각화 전용)
- [ ] nav-links:hover violet → ink
- [ ] section-label `hl-orange/hl-teal` 동시 사용 → 단일 색

### Phase 2.5 — 이모지 → SVG 라인 아이콘

**문제**: P0에서 `aria-hidden`만 적용. 시각적 일관성은 미해결.

**합의안**:
- [ ] Lucide Icons outline 24px 1.5px stroke 채택
- [ ] 색은 `var(--ink-muted)` 단일
- [ ] 또는 더 과감히 — 아이콘 제거하고 숫자(`how-step-num`처럼) 또는 단어로 대체

### Phase 2.6 — Legal 페이지 디자인 통합

**문제**: terms/privacy가 마케팅 페이지와 시각 분리됨. "법무가 PDF 붙인 느낌".

**합의안**:
- [ ] eyebrow `LEGAL · 시행일 2026.03.01`
- [ ] 우측 sticky 조항 anchor TOC
- [ ] 표 헤더 amber-soft 배경
- [ ] 인용 콜아웃 `--surface-warm`
- [ ] H2 22~24px / H3 17px / p 16px 위계 강화
