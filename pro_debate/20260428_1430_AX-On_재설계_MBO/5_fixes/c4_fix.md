## 가설
"디자인 일관성 → 사용자 신뢰 → 회원가입·프로젝트 접수 전환률 향상"
- 정량 X% 목표는 Phase A0 종료 시점 베이스라인 데이터로 설정.
- Phase A1은 가설 검증 가능 상태로의 전환이 목표.

## 비즈니스 동기
- AX-On 핵심 전환 2건: (a) 기업 'AX 프로젝트 접수' 폼, (b) AI 전문가 '회원가입'
- 8 페이지 4그룹 깔때기:
  - **Conversion** (index, ax-project): 직접 전환
  - **Content** (about-ax, methodology): 신뢰 형성
  - **Community** (community, pool): 참여·소속감
  - **Legal** (terms, privacy): 규제 준수·신뢰 보강

## Phase 분리

### Phase A0 — 측정 인프라 + 베이스라인 (4~5주)
1. Vercel Analytics 활성화 + 이벤트 트래킹 코드 (그룹 퍼널 포함)
2. **🆕 N 측정 + 베이스라인 수집 (1~5주, 통합 Task)** — N≥100이면 1주 종료, 30≤N<100이면 +3주(총 4주), N<30이면 4주 종료 후 측정 불가 처리. *(DA w4 반영)*
3. Hero CTA 클릭률·페이지 도달률·Lighthouse 모바일 베이스라인 수집
4. **🆕 베이스라인 기반 Phase B 임계값 재조정 + 출처 명시** — *(DA n1 반영)*
   - 옵션 A: HubSpot 2024 Conversion Benchmarks Report (또는 동등 공인 출처)
   - 옵션 B: 자체 베이스라인 4주 데이터 단독 사용 (외부 벤치마크 미사용 명시)
   - PO가 옵션 A/B 선택 후 임계값 표 갱신
5. **🆕 A0 산출물**: N 데이터 + 베이스라인 KPI + 측정 도구 검증 + 임계값 재조정 표 (출처 명시)
6. **🆕 A0 게이트 통과 조건 (3건 충족 필수)** — *(DA n4 반영, '정상 운영' 정량화)*
   - (a) Vercel Analytics 정상 운영 ≥ 4주 + **누락 이벤트율 ≤5%** + **일평균 세션 수 ≥10**
   - (b) N 데이터 확보 — **페이지별 + 시간대별(주중/주말 분리)** + **N≥30 시 95% 신뢰 구간 / N<30 시 점추정 + 4주 추세선** *(v5.1 — 통계 분기)*
   - (c) PO 승인 (베이스라인 리포트 검토 후)
   - 3건 충족 시에만 A1 진입

### Phase A1 — 시각 통일 (6주, A0 통과 후)
1. 토큰 4축 정의 (common.css)
2. 공통 섹션 클래스 (.sec-header, .eyebrow, .sec-title, .sec-lead)
3. 4그룹 분류 + 그룹별 보조 액센트 (Legal slate-500 1차)
4. methodology.html teal → amber + 정렬 통일
5. weight·아이콘 토큰 적용
6. grep 검수 + Lighthouse 재측정 + KPI 비교

### Phase B — 페이지별 깊은 재구성 (조건부)
- Phase B 진입 ROI 임계값(2축 표) 충족 시 진행
- N<30 시 PO 별도 승인 필수 (자동 진입 차단)

| N (일평균 방문자) | 측정 기간 | 비즈니스 KPI 사용 | Phase B 진입 |
|---|---|---|---|

### 🆕 N<30 PO 승인 기준 (3건 모두 충족 필수, DA n3 반영)
| # | 기준 | 측정 |
|---|------|------|
| (a) | 생산성 KPI 모두 충족 | 리드타임 -20% + **CSS 중복 라인 -20%** + 토큰 위반 0건 *(v5.1 — 단위 통일)* |

## Phase B Go/No-Go 임계값 (잠정값 — A0 종료 시 재조정)

> **임계값 출처**: 아래 +3%, -20%는 잠정값. Phase A0 Task 4에서 PO가 옵션 A(외부 벤치마크) 또는 옵션 B(자체 4주 데이터 단독)를 선택 후 재조정. 재조정 결과는 본 표에 갱신 반영.

**2축 임계값 — 두 축 동시 평가**

| 비즈니스 KPI Δ | 생산성 KPI Δ (리드타임) | 결정 |
|---|---|---|
| ≥ +3% | ≥ -20% | **즉시 Phase B 진입** |
| ≥ +3% | < -20% | 추가 측정 4주 |
| +1~3% | ≥ -20% | 추가 측정 4주 |
| +1~3% | < -20% | 추가 측정 8주 또는 가설 재정의 |
| < +1% | < -20% | **Phase B 중단 + 가설 폐기** |

**비즈니스 KPI**: Hero CTA 클릭률, /pool·/ax-project 도달률
**생산성 KPI**: 신규 페이지 제작 리드타임, 컴포넌트 재사용률, 토큰 위반 건수
**N < 30 분기**: 비즈니스 축 = "측정 불가", 생산성 KPI 단독 + 위 PO 승인 기준 3건 충족 시에만 진입

## 4그룹화 + 보조 액센트

| 그룹 | 페이지 | 1차 컬러 | 보조 액센트 | 시각 정체성 |
|------|-------|---------|-----------|-----------|
| **Conversion** | index, ax-project | --brand (amber #f59e0b) | --brand-700 (강) | 행동 유도 |
| **Content** | about-ax, methodology | --brand (amber) | --brand-100~300 (약) | 차분·신뢰 |
| **Community** | community, pool | --brand + **--accent-warm** | --accent-warm (보조) | 활기·소속감 |
| **Legal** | terms, privacy | --accent-neutral (slate-500) | --accent-neutral-strong (slate-700) | 규제·신뢰 |

> **🆕 v4 → v5 변수명 통일 (DA w2 반영)**: 'warm-orange' → '--accent-warm'으로 변수명 일치. 모든 1차/보조 컬러를 토큰 변수명으로 표기.

### 🆕 신규 페이지 그룹 배정 룰 (3단계 적용, DA w1 반영)

신규 페이지는 다음 3단계 룰을 순서대로 적용하여 그룹 결정:

| 단계 | 룰 | 예시 |
|------|----|------|
| 1 | **URL 패턴** | `/legal/*`, `/terms`, `/privacy` → Legal |
| 2 | **전환 목적** (1단계 미적용 시) | `<form>` 폼 제출 페이지 → Conversion |
| 3 | **콘텐츠 유형** (1·2단계 미적용 시) | `<article>` 또는 가이드 → Content / 사용자 참여 → Community |

PR 머지 조건: 신규 페이지의 그룹 매핑 명시 + 적용 룰 단계 표기.

## 단일 디자인 토큰 4축

### 축 1: 컬러
```css
--brand: #f59e0b
--brand-100, --brand-300, --brand-500, --brand-700, --brand-900
--accent-warm: #fb923c
--accent-neutral: #64748b (slate-500, Legal 1차)
--accent-neutral-strong: #334155 (slate-700, Legal 강조)
--text-primary, --text-muted, --bg-base, --bg-elevated, --border-subtle
```

> **다크모드 슬롯**: Phase B 종료 후 별도 MBO에서 다룬다. 토큰 구조는 semantic 네이밍으로 확장 가능.

### 축 2: 타이포
```css
--fs-hero, --fs-page-title, --fs-section, --fs-card, --fs-lead, --fs-body, --fs-small
--fw-regular: 400, --fw-medium: 500, --fw-semibold: 600, --fw-bold: 700, --fw-black: 900
```

### 축 3: 간격 (8px 기반)
```css
--sp-1: 4px, --sp-2: 8px, --sp-3: 12px, --sp-4: 16px, --sp-6: 24px,
--sp-8: 32px, --sp-12: 48px, --sp-16: 64px, --sp-24: 96px
```

### 축 4: 컴포넌트
```css
--r-sm: 4px, --r-md: 8px, --r-lg: 12px, --r-xl: 20px, --r-full: 9999px
--sh-1, --sh-2, --sh-3
--icon-sm: 16px, --icon-md: 20px, --icon-lg: 24px, --icon-xl: 32px
icon stroke-width: 1.5px (line) / fill (solid) 2종
```

### 거버넌스
- 토큰 추가 시 `css/common.css` :root에만 정의, 컴포넌트에서 직접 hex 금지
- grep `font-size:\s*\d+px` outside :root → 0건 = 토큰화 완료
- weight·아이콘도 동일 grep 검사
- **신규 토큰 PR 체크리스트**:
  - [ ] 4축 정합성 (컬러/타이포/간격/컴포넌트 어디 속하는지)
  - [ ] 네이밍 규칙 — `--{category}-{scale}` 형식 (예: --fs-section, --sp-4, --brand-500)
  - [ ] grep 검사 통과 (해당 토큰 카테고리)
