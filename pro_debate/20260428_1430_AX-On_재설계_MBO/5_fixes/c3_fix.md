## 가설
"디자인 일관성 → 사용자 신뢰 → 회원가입·프로젝트 접수 전환률 향상"
- **이 가설의 정량 X% 목표는 Phase A0 종료 시점에 베이스라인 데이터를 갖고 설정한다.**
- Phase A1(시각 통일)은 가설 검증이 아니라 가설 검증 가능 상태로의 전환이 목표.

## 비즈니스 동기
- AX-On은 (a) 기업의 'AX 프로젝트 접수' 폼 제출, (b) AI 전문가의 '회원가입' 두 전환이 핵심
- 8개 페이지가 4그룹으로 분류되며 각 그룹은 깔때기의 다른 위치를 담당:
  - **Conversion 그룹** (index, ax-project): 직접 전환
  - **Content 그룹** (about-ax, methodology): 신뢰 형성
  - **Community 그룹** (community, pool): 참여·소속감
  - **Legal 그룹** (terms, privacy): 규제 준수·신뢰 보강

## Phase 분리

### Phase A0 — 측정 인프라 + 베이스라인 (4주, 선행 필수)
1. Vercel Analytics 활성화 + 이벤트 트래킹 코드 삽입 (그룹 간 퍼널 이동 이벤트 포함)
2. 페이지별 일평균 방문자 N 측정 (주중/주말 편차 포함)
3. Hero CTA 클릭률·페이지 도달률 베이스라인 수집
4. Lighthouse 모바일 베이스라인 측정
5. **🆕 베이스라인 기반 Phase B 임계값 재설정** (DA n1 반영) — +3%/-20%는 잠정값, A0 종료 시 업계 벤치마크·자체 베이스라인으로 재조정
6. **A0 산출물**: N 데이터 표 + 베이스라인 KPI 표 + 측정 도구 검증 리포트 + **Phase B 임계값 재조정 표**
7. **🆕 A0 종료 게이트 통과 조건 (3건 모두 충족 필수, DA n4 반영)**:
   - (a) Vercel Analytics 정상 운영 ≥ 4주
   - (b) N 데이터 확보 (페이지별·시간대별)
   - (c) PO 승인 (베이스라인 리포트 검토 후)
   - → 3건 충족 시에만 A1 진입

### Phase A1 — 시각 통일 (6주, A0 통과 후)
1. 토큰 4축 정의 (컬러·타이포·간격·컴포넌트)
2. 공통 섹션 클래스 (.sec-header, .eyebrow, .sec-title, .sec-lead)
3. methodology.html teal → amber 일괄 치환
4. 8페이지를 4그룹으로 분류 + 그룹별 보조 액센트 적용
5. 정렬 규칙 적용 (페이지·섹션 헤더 가운데, 본문 왼쪽)
6. **A1 산출물**: 토큰 4축 + 4그룹 적용 + KPI 변화 리포트 (A0 베이스라인 대비)

### Phase B — 페이지별 깊은 재구성 (조건부, A1 측정 후)
- Phase B 진입 ROI 임계값(2축 표, 아래) 충족 시 진행
- **🆕 N<30 시 자동 진입 차단** — 비즈니스 KPI 측정 불가이므로 생산성 KPI만 충족해도 PO 별도 승인 없이는 Phase B 미진입 (DA n3 반영)

### N 분기 룰

| N (일평균 방문자) | 측정 기간 | 비즈니스 KPI 사용 | Phase B 진입 |
|---|---|---|---|
| N ≥ 100 | 1주 | 사용 (전환률·도달률) | 임계값 표 자동 적용 |
| 30 ≤ N < 100 | 4주 | 사용 (보수적 해석) | 임계값 표 자동 적용 |
| N < 30 | 측정 불가 | 보류, 생산성 KPI 사용 | **PO 별도 승인 필수** (자동 진입 차단) |

## Phase B Go/No-Go 임계값 (잠정값 — A0 종료 시 재조정)

> **🆕 임계값 출처 명시 (DA n1 반영)**: 아래 +3%, -20%는 잠정값. Phase A0 Task 5에서 실제 베이스라인과 업계 벤치마크(B2B SaaS 랜딩 평균 전환률 변화 폭)에 기반해 재조정. 재조정 결과는 PO 승인 후 본 표에 갱신 반영.

**2축 임계값 — 두 축 동시 평가**

| 비즈니스 KPI Δ | 생산성 KPI Δ (리드타임) | 결정 |
|---|---|---|
| ≥ +3% | ≥ -20% | **즉시 Phase B 진입** |
| ≥ +3% | < -20% | 추가 측정 4주 |
| +1~3% | ≥ -20% | 추가 측정 4주 |
| +1~3% | < -20% | 추가 측정 8주 또는 가설 재정의 |
| < +1% | < -20% | **Phase B 중단 + 가설 폐기** |

**비즈니스 KPI**: Hero CTA 클릭률, /pool·/ax-project 도달률
**생산성 KPI**: 신규 페이지 제작 리드타임, 컴포넌트 재사용률, 토큰 위반 건수
**N < 30 분기**: 비즈니스 KPI 축 = "측정 불가"로 표기, 생산성 KPI 단독 평가 → **PO 별도 승인 시에만** Phase B 진입

## 4그룹화 + 보조 액센트

| 그룹 | 페이지 | 1차 컬러 | 보조 액센트 | 시각 정체성 |
|------|-------|---------|-----------|-----------|
| **Conversion** | index, ax-project | amber #f59e0b | amber-700 (강) | 행동 유도 — 채도·강도 강조 |
| **Content** | about-ax, methodology | amber #f59e0b | amber-100~300 (약) | 차분·신뢰 — 톤 약화 |
| **Community** | community, pool | amber + warm-orange | warm-orange (보조) | 활기·소속감 — 보조색 도입 |
| **Legal** | terms, privacy | **slate-500** | slate-700 (강조) | 규제·신뢰 — 무채색 |

> **🆕 v3 → v4 정정 (DA n2 반영)**: Legal 1차 컬러 `slate-700` → `slate-500`으로 정정 (토큰 축 1과 정합). slate-700은 토큰에 신규 추가하여 보조 강조용으로 사용.

→ "단일 시스템 + 4그룹 정체성"으로 표현 정정. amber 톤 변주뿐이 아니라 그룹별 레이아웃 패턴·인터랙션 밀도·타이포 스케일도 차별화.

```css
--text-primary, --text-muted, --bg-base, --bg-elevated, --border-subtle
```

> **🆕 다크모드 토큰 슬롯 (DA n5 부분 수용 — Phase B 이후 검토 항목)**
> ```css
> /* :root[data-theme=dark] { /* TODO: Phase B 이후 별도 검토 — 현재 운영 우선순위 낮음 */ }
> ```
> 현재 AX-On은 다크모드 미지원. 다크모드 도입은 Phase B 종료 후 별도 MBO에서 다룬다 (E2 의견 반영). 토큰 구조는 미래 확장 가능한 semantic 네이밍으로 설계되어 있어 추후 도입 시 :root[data-theme=dark] 슬롯만 추가하면 된다.

```css
icon stroke-width: 1.5px (line) / fill (solid) 2종
```

### 거버넌스
- 토큰 추가 시 `css/common.css` :root에만 정의, 컴포넌트에서 직접 hex 금지
- grep `font-size:\s*\d+px` outside :root → 0건이 토큰화 완료 기준
- weight·아이콘도 동일 grep 검사
- **신규 토큰 추가 승인**: PR 시 PO 1인 체크리스트 검수 (4축 정합성·네이밍 규칙 준수 확인)
