## 최상위 목표 (정직 재명명)
"전 페이지에 단일 디자인 시스템 토큰 4축(컬러·타이포·간격·컴포넌트)을 통일 적용하고,
8개 페이지를 4그룹으로 분류하여 그룹별 보조 액센트로 정체성을 보존하며,
별도 측정 인프라를 선행 구축하여 비즈니스 가치는 측정 후 판단한다."

## 가설 (DA n1 합의에 따라 검증 시점 명시)
"디자인 일관성 → 사용자 신뢰 → 회원가입·프로젝트 접수 전환률 향상"
- **이 가설의 정량 X% 목표는 Phase A0 종료 시점에 베이스라인 데이터를 갖고 설정한다.**
- Phase A1(시각 통일)은 가설 검증이 아니라 가설 검증 가능 상태로의 전환이 목표.

## 비즈니스 동기
- AX-On은 (a) 기업의 'AX 프로젝트 접수' 폼 제출, (b) AI 전문가의 '회원가입' 두 전환이 핵심
- 8개 페이지가 4그룹으로 분류되며 각 그룹은 깔때기의 다른 위치를 담당:
  - **Conversion 그룹** (index, ax-project): 직접 전환
  - **Content 그룹** (about-ax, methodology): 신뢰 형성
  - **Community 그룹** (community, pool): 참여·소속감
  - **Legal 그룹** (terms, privacy): 규제 준수·신뢰 보강

## Phase 분리 (DA n1 반영)

### Phase A0 — 측정 인프라 + 베이스라인 (4주, 선행 필수)
1. Vercel Analytics 활성화 + 이벤트 트래킹 코드 삽입
2. 페이지별 일평균 방문자 N 측정 (주중/주말 편차 포함)
3. Hero CTA 클릭률·페이지 도달률 베이스라인 수집
4. Lighthouse 모바일 베이스라인 측정
5. **A0 산출물**: N 데이터 표 + 베이스라인 KPI 표 + 측정 도구 검증 리포트
6. **A0 종료 게이트**: N에 따라 다음 분기 결정 (아래 N 분기 룰)

### Phase A1 — 시각 통일 (6주, A0 통과 후)
1. 토큰 4축 정의 (컬러·타이포·간격·컴포넌트)
2. 공통 섹션 클래스 (.sec-header, .eyebrow, .sec-title, .sec-lead)
3. methodology.html teal → amber 일괄 치환
4. 8페이지를 4그룹으로 분류 + 그룹별 보조 액센트 적용
5. 정렬 규칙 적용 (페이지·섹션 헤더 가운데, 본문 왼쪽)
6. **A1 산출물**: 토큰 4축 + 4그룹 적용 + KPI 변화 리포트 (A0 베이스라인 대비)

### Phase B — 페이지별 깊은 재구성 (조건부, A1 측정 후)
- Phase B 진입 ROI 임계값(2축 표, 아래) 충족 시 진행

### N 분기 룰 (DA n4 반영)

| N (일평균 방문자) | 측정 기간 | 비즈니스 KPI 사용 |
|---|---|---|
| N ≥ 100 | 1주 | 사용 (전환률·도달률) |
| 30 ≤ N < 100 | 4주 | 사용 (보수적 해석) |
| N < 30 | 측정 불가 | **보류, 대신 생산성 KPI 사용** (신규 페이지 제작 리드타임·컴포넌트 재사용률·토큰 위반 건수) |

## Phase B Go/No-Go 임계값 (DA n2 반영, E1 2축 제안 채택)

**2축 임계값 — 두 축 동시 평가**

| 비즈니스 KPI Δ | 생산성 KPI Δ (리드타임) | 결정 |
|---|---|---|
| ≥ +3% | ≥ -20% | **즉시 Phase B 진입** |
| ≥ +3% | < -20% | 추가 측정 4주 |
| +1~3% | ≥ -20% | 추가 측정 4주 |
| +1~3% | < -20% | 추가 측정 8주 또는 가설 재정의 |
| < +1% | < -20% | **Phase B 중단 + 가설 폐기** |

**비즈니스 KPI**: Hero CTA 클릭률, /pool·/ax-project 도달률
**생산성 KPI**: 신규 페이지 제작 리드타임, 컴포넌트 재사용률, 토큰 위반 건수
**N < 30 fallback**: 비즈니스 KPI 축 = "측정 불가"로 표기, 생산성 KPI 단독 평가

## 4그룹화 + 보조 액센트 (DA n3 반영)

| 그룹 | 페이지 | 1차 컬러 | 보조 액센트 | 시각 정체성 |
|------|-------|---------|-----------|-----------|
| **Conversion** | index, ax-project | amber #f59e0b | amber-700 (강) | 행동 유도 — 채도·강도 강조 |
| **Content** | about-ax, methodology | amber #f59e0b | amber-100~300 (약) | 차분·신뢰 — 톤 약화 |
| **Community** | community, pool | amber + warm-orange | warm-orange (보조) | 활기·소속감 — 보조색 도입 |
| **Legal** | terms, privacy | slate-700 | slate-500 (보조) | 규제·신뢰 — 무채색 |

→ "단일 시스템 + 4그룹 정체성"으로 표현 정정. amber 톤 변주뿐이 아니라 그룹별 레이아웃 패턴·인터랙션 밀도·타이포 스케일도 차별화 (E1 추가 제안).

## 단일 디자인 토큰 4축 (Cycle 2 E1·E3 보강 반영)

### 축 1: 컬러
```css
--brand: #f59e0b (amber, 1차)
--brand-100, --brand-300, --brand-500, --brand-700, --brand-900 (5단계 톤)
--accent-warm: #fb923c (Community 그룹 보조)
--accent-neutral: slate-500 (Legal 그룹 보조)
--text-primary, --text-muted, --bg-base, --bg-elevated, --border-subtle
```

### 축 2: 타이포
```css
/* 사이즈 (clamp 기반 fluid — Phase A1에 도입) */
--fs-hero, --fs-page-title, --fs-section, --fs-card, --fs-lead, --fs-body, --fs-small

/* weight (Cycle 2 E3 보강) */
--fw-regular: 400, --fw-medium: 500, --fw-semibold: 600, --fw-bold: 700, --fw-black: 900
```

### 축 3: 간격 (8px 기반)
```css
--sp-1: 4px, --sp-2: 8px, --sp-3: 12px, --sp-4: 16px, --sp-6: 24px,
--sp-8: 32px, --sp-12: 48px, --sp-16: 64px, --sp-24: 96px
```

### 축 4: 컴포넌트
```css
/* radius */
--r-sm: 4px, --r-md: 8px, --r-lg: 12px, --r-xl: 20px, --r-full: 9999px

/* shadow elevation */
--sh-1, --sh-2, --sh-3

/* 아이콘 (Cycle 2 E3 보강) */
--icon-sm: 16px, --icon-md: 20px, --icon-lg: 24px, --icon-xl: 32px
icon stroke-width: 1.5px (line) / fill (solid) 2종
```

### 거버넌스
- 토큰 추가 시 `css/common.css` :root에만 정의, 컴포넌트에서 직접 hex 금지
- grep `font-size:\s*\d+px` outside :root → 0건이 토큰화 완료 기준
- weight·아이콘도 동일 grep 검사

## KPI (DA n1 반영, 모두 측정값/목표값 분리)

| 지표 | 베이스라인 (A0 산출물) | A1 종료 목표 | 측정 방법 | 분류 |
|------|----------------------|------------|----------|------|
| 페이지 간 색 일관성 | 측정 N/A | teal 사용 0건 | grep | 위생 |
| 토큰 적용률 | 측정 N/A | hard-coded 0건 | grep | 위생 |
| 정렬 일관성 | 측정 N/A | 모든 섹션 헤더 패턴 준수 | 시각 검수 | 위생 |
| 컴포넌트 재사용률 | A0에서 측정 | A1에서 +20% | 코드 분석 | 생산성 |
| 신규 페이지 제작 리드타임 | A0에서 측정 | A1에서 -20% | 작업 로그 | 생산성 |
| Hero CTA 클릭률 | A0에서 측정 | A1에서 +3% (N≥30 시) | Vercel Analytics | 비즈니스 |
| Hero → /pool 도달률 | A0에서 측정 | A1에서 +3% (N≥30 시) | Vercel Analytics | 비즈니스 |
| Hero → /ax-project 도달률 | A0에서 측정 | A1에서 +3% (N≥30 시) | Vercel Analytics | 비즈니스 |
| Lighthouse 모바일 | A0에서 측정 | 베이스라인 -10 미만 회귀 없음 | Lighthouse CI | 성능 |

→ "측정값 확보"가 KPI가 아니라 A0 산출물임을 명확히 분리. A1의 KPI는 모두 베이스라인 대비 정량 목표.
